结构对齐 · 流式状态机 · 语义补齐

请求转换

Anthropic 的 content 是块数组；OpenAI 是扁平 role + content 与 tool_calls。

AnthropicOpenAI说明
systemrole: "system"多块拼接
user 文本role: "user"字符串或 text part
imageimage_urlbase64 → data URI
assistant.tool_usetool_calls[]id / name / arguments
user.tool_resultrole: "tool"必须紧跟对应 assistant
thinking 历史—请求侧通常丢弃
顺序是硬约束。 OpenAI 要求 tool 消息紧跟带 tool_calls 的 assistant。网关在 convertMessages 里拆分、重排并清洗孤儿 tool 消息。

input_schema → function.parameters；tool_choice: "any" → "required"。客户端的 web_search_* 由网关内部执行。

模型路由：精确别名 → haiku/sonnet/opus 槽位 → 剥离 [1m]。Thinking 的 budget_tokens 映射为 reasoning_effort（low / medium / high）。

响应转换

  1. reasoning_content→ thinking 块 + 假 signature
  2. <think> 标签正则拆出 thinking 与 text
  3. tool_calls→ tool_use 块
  4. 组装 messagestop_reason · usage

stop → end_turn；tool_calls → tool_use；length → max_tokens。

流式状态机

OpenAI 增量 chunk 由 StreamConverter 还原为严格顺序：

  • message_start元信息
  • content_block_start开块 text / thinking / tool_use
  • content_block_deltatext_delta · thinking_delta · input_json_delta
  • content_block_stop关块
  • message_delta + message_stopstop_reason 与 usage

半截标签

缓冲 + couldBeTag / safeCut，避免标签字符泄漏。

思考与文本

pendingThinking 先 flush，再开 text 块。

工具增量

按 index 维护 Map，拼 arguments，发 input_json_delta。

web_search

状态机 pause，网关自搜后以 Anthropic 块续流。

一句话

网关不增强模型能力。它做结构对齐、流式状态机、语义补齐。Claude Code 以为在跟 Anthropic 说话，实际上请求已完整翻译成 OpenAI 格式，发往任意兼容上游。

对照代码从 convertMessages、buildOpenAIRequestBody、convertResponse、StreamConverter 读起。
